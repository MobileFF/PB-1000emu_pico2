# 利用ガイド

このガイドでは、PB-1000 エミュレータのセットアップ方法、起動方法、および操作方法について説明します。

---

## 1. 初期設定

### ROM イメージ

エミュレータが動作するためには、オリジナルの CASIO PB-1000 ROM イメージが必要です。これらはプロジェクトに含まれていません。

- `rom0.bin`: 内部 ROM（6KB、アドレス 0x0000–0x17FF）
- `rom1.bin`: システム ROM（32KB、アドレス 0x8000–0xFFFF、Bank 0）
- `charset.bin`（`/roms/` に配置、省略可）: DRAW_CHAR モードで文字コードを実際のピクセルとして描画するためのグリフデータ。存在しない場合はエラーにならないが、DRAW_CHAR で描画される文字が空白ピクセルになる

### ディレクトリ構造（SD カード / フラッシュ）

```text
/                          # Pico フラッシュルート
├── main.py                # エントリポイント
├── pb1000.ini             # グローバル設定（省略可）
└── roms/                  # ROM / RAM フォールバック置き場
    ├── rom0.bin
    └── rom1.bin

/sd/                       # SD カード（推奨）
├── pb1000.ini             # グローバル設定上書き（省略可）
├── rams/                  # プロファイルディレクトリ（起動時選択 & RAM セーブ/ロード兼用）
│   ├── default/           # "default" プロファイル
│   │   ├── pb1000.ini     # プロファイル個別設定（省略可）
│   │   ├── rom0.bin       # プロファイル個別 ROM（省略可）
│   │   ├── ram0.bin       # 保存された標準 RAM
│   │   ├── ram1.bin       # 保存された拡張 RAM1（省略可）
│   │   ├── ram2.bin       # 保存された拡張 RAM2（Bank2、省略可）
│   │   ├── ram3.bin       # 保存された拡張 RAM3（Bank3、省略可）
│   │   └── regs.json      # 保存された CPU レジスタ
│   └── bench/             # 追加プロファイルの例
├── disks/                 # 仮想 FDD ディスクイメージ
│   └── disk1.img
└── screenshots/           # スクリーンショット保存先
```

設定の優先順位（低→高）: フラッシュ `/pb1000.ini` → `/sd/pb1000.ini` → `<プロファイル>/pb1000.ini`

## 2. 起動フロー

1. Pico 2 に電源を入れる。
2. **プロファイル選択 UI** が表示される。SD カード上の `/sd/rams/` を走査してリストアップ。
   - 上下キーまたはタッチでプロファイルを選択し EXE / タッチで決定。プロファイル数が
     画面に入りきらない場合は自動的にスクロールする。
   - タイムアウト（デフォルト 30 秒）で `default_profile` の設定値が自動選択される。
   - **F1**: BIOS 風の設定メニューを開く（下記参照）。
   - **F12**: 確認ダイアログの後、起動せずに MicroPython の REPL へ抜ける（下記参照）。
3. 選択したプロファイルのステートが自動ロードされ、PB-1000 LCD ベゼルが表示される。
4. ステートファイルが見つからない場合はコールドブート（新規起動）。

### 起動ステータス表示（プロファイル選択後〜起動完了まで）

プロファイルを選択した直後から、ROM/RAM のロードや NTP 同期などエミュレータ起動が完了する
までの間、物理LCD上に以下を表示します（HDMIミラーがプロファイル選択画面を引き継いだ場合は
表示されません）。

- **左上**: 選択したプロファイル名
- **右上**: 現在の年月日時分秒（Picoの内蔵RTC。`[ntp]`が有効な場合は同期完了時点で正しい
  時刻へ切り替わる）
- **最下部**: REPLに出力された最新のログ1行（起動処理の進行状況をそのまま表示）

プロファイル名・時計はそれぞれ `[overlay] show_profile_name` / `show_clock` で表示・非表示を
切り替えられます（BIOS 風設定メニュー(下記)の主要キー一覧に最初から表示されます。詳細は
[config_guide.md](config_guide.md) §15）。

### BIOS 風設定メニュー（F1）

プロファイル選択画面で **F1** を押すと、`pb1000.ini` を実機の画面上から直接編集できる
BIOS 風の設定メニューが開きます（`mp/setup_menu.py`）。ROM/RAM のロードや CPU の起動より前の
最も安全なタイミングで動作する、EMULATOR MENU（Win+F7、エミュレータ実行中のみアクセス可）
とは別の独立したメニューです。

1. **編集対象の選択**: 内蔵フラッシュの `/pb1000.ini`、SD カードの `/sd/pb1000.ini`
   （SD がマウントされている場合のみ表示）、各 RAM プロファイルの `pb1000.ini` の
   いずれかを選びます。
2. **キーの編集**: 上下キーで項目を選び EXE で編集します（bool 型は EXE で ON/OFF 切り替え、
   enum 型は EXE または左右キーで選択肢を循環、int 型・str 型は EXE で数値/文字列の入力画面へ）。
   BS でそのキーの設定を削除（未指定＝デフォルト値に戻る）。
   - デフォルトでは主要なキーのみ表示されます（`Show ALL keys` を ON にすると全キー表示）。
   - `[hdmi]` セクションのキーなど、内蔵フラッシュ限定のキー（[config_guide.md](config_guide.md)
     §1参照）は、SD カード／プロファイル別 ini を編集中は表示されません（設定しても
     読み込み時に無視されるため）。
3. **Save & Exit (reset)**: 変更を選択した ini ファイルへ書き込み、確認後に `machine.reset()`
   で実機を再起動します。再起動後の起動シーケンスが新しい設定を最初から読み込み直します。
4. **Discard & Back**: 変更を破棄してプロファイル選択画面に戻ります（未保存の変更がある
   場合は確認ダイアログが出ます）。

### F12: REPL へ抜ける（開発・復旧用）

プロファイル選択画面で **F12** を押すと確認ダイアログが出て、Yes を選ぶと `main.py` の実行を
安全に中断して MicroPython の REPL へ戻ります（ROM/RAM のロードや CPU の起動は一切行われません）。

これは開発・復旧用のショートカットです。`main.py` は起動のたびに自動実行されるため、
起動後半の処理や対話ループにバグが潜んでいた場合、そこでフリーズ・クラッシュすると REPL
接続そのものが塞がれてしまい、復旧には BOOTSEL モード＋ `flash_nuke.uf2` でのフルワイプが
必要になりかねません。F12 は、この画面（ROM/RAM のロードや CPU 起動より前）で押せる限り
常に安全に抜けられる「避難口」として用意されています。

## 3. キーボード操作

### 特殊機能キー

| PC キー | 機能 | 備考 |
| :--- | :--- | :--- |
| **NumLock** | リセット | ハードウェアリセット（PC=0x0000） |
| **F11** | Save State | RAM・レジスタを現在のプロファイルに保存 |
| **PrintScreen** | スクリーンショット | LCD 内容を `/sd/screenshots/` に `.pbm` として保存 |
| **Win（GUI）+ F7** | エミュレータメニュー | 各種機能の切り替えメニューを開く |
| **Win（GUI）+ F6** | ディスクスワップ | 仮想 FDD のディスクイメージを切り替える |
| **Win（GUI）+ Esc** | エミュレータ終了 | MicroPython REPL に戻る（※GP0/GP1 配線の UART REPL 経由。[Hardware Guide](hardware_guide.md) 参照） |
| **Esc** | BREAK | BASIC プログラムの停止 / エラー解除 |
| **Enter** | EXE | コマンドの実行 |
| **Backspace** | BS | 文字の削除 |
| **Insert** | INS | 挿入モード |
| **矢印キー** | カーソル移動 | ↑↓←→（長押しでキーリピート） |
| **Alt（L/R）** | Shift | PB-1000 の Shift キー |
| **F1 – F4** | TK13 – TK16 | ファンクションキー |

### カーソルキーリピート

矢印キー（↑↓←→）を長押しすると、約 400ms の初期遅延の後、カーソルが自動的に繰り返し移動します。
これはエミュレータ側で ROM の KEY_INT ISR に対してリリース／再押下サイクルを合成することで実現しています。

### キーマッピング

エミュレータは HID スキャンコードを PB-1000 キーマトリクス（13 行 × 12 列）に変換します。

- アルファベット・数字: 直接マッピング
- 記号: PB-1000 相当キーにマッピング（例: PC の `Shift+2` → PB-1000 の `"`）
- **LCKEY / MENU / CAL**: それぞれ F5 / F6 / F7 にマッピング
- 詳細なマッピングテーブルは `mp/keymap.py` / `mp/keymap.json` を参照

## 4. タッチインターフェースと FuncKeyBar

### タッチパネル（TK1–TK16）

PB-1000 の 16 キータッチパネルは LCD のタッチスクリーンでエミュレートされます。

- LCD 表示領域（192×32 ピクセル相当エリア）をタップすると、対応するタッチキー（TK1–TK16）が発火。
- LCD 領域を 4×4 のグリッドに分割してタッチ座標を変換。
- このタッチ判定エリアは常に実機物理タッチパッド相当の高さ（32ドット×`scale`）で固定です。
  `[display] lcd_height = 64`（拡張モード）にしても、タッチ判定エリアの高さは変わりません
  （実機にはこの拡張に対応するタッチパッドが存在しないため）。

### FuncKeyBar

画面下部に LCKEY・MENU・CAL・CALC の 4 キー（またはそれに対応する画像）が常時表示されます。
タッチパネルでこのバーをタップすると対応キーが押下されます。表示位置は `[display] lcd_height`
と `scale` に応じて自動的に計算されます。

### タッチパネルのキャリブレーション（XPT2046）

タッチパネルコントローラ XPT2046 は、LCD モジュールごとにタッチフィルムの取り付け向きが
異なるため、軸の入れ替え・反転や座標オフセットの調整が必要になる場合があります。
`pb1000.ini` の `[touch]` セクションで調整します。

- `swap_xy` / `x_inv` / `y_inv`: タッチ座標の X/Y 入れ替え・各軸反転。
  内蔵デフォルトは ILI9341 が `swap_xy=true, x_inv=false, y_inv=false`、
  ST7796 が `swap_xy=true, x_inv=true, y_inv=true`。
  これらは起動時（SD カードマウント前）に内蔵フラッシュの `/pb1000.ini`（および
  `/roms/pb1000.ini`）からのみ読み込まれるため、SD カードやプロファイル別 ini には
  反映されません。
- `x_offset` / `y_offset`（LCD タッチエリア用）、`funckey_x_offset` / `funckey_y_offset`
  （FuncKeyBar 用）: ピクセル単位の座標補正オフセット。こちらは SD カード・プロファイル別
  ini でも上書き可能です。
- ILI9341 / ST7796 両方の設定を同じ `[touch]` セクションに共存させられます。
  key の先頭に `ili9341.` または `st7796.` を付けると、`[display] driver` で選択されている
  ドライバのときだけ適用されます（例: `st7796.y_offset = -4`）。プレフィックス無しの key は
  どちらのドライバでも（ドライバ別の値で上書きされなければ）適用されます。
- 各項目の内蔵デフォルト値・記述例は `pb1000.ini` 内のコメントを参照してください。

## 6. シリアル機能

> [!NOTE]
> かつてここには **シリアルコンソール**（LCD の表示内容を文字として認識し、コンソール UART
> GP4/GP5 にリアルタイム出力する機能。`[keyboard] enable_uart_kbd` で ON/OFF）がありましたが、
> 2026-08-22 に廃止されました。同じ GP4/GP5・UART1 を使っていた UART キーボード入力機能
> （シリアル端末から PB-1000 のキーを打鍵する機能）も同時に廃止されています。RS-232C
> （PIO UART、GP6/GP13）はこの廃止とは無関係で、以下の通り引き続き利用できます。

### RS-232C（PIO UART）

PIO ソフト UART（デフォルト GP6 TX / GP13 RX）で CASIO PB-1000 の RS-232C インターフェースをエミュレートします。

- MMIO アドレス 0x0C00–0x0C03（SIO レジスタ）に接続。
- TX/RXピンは `pb1000.ini` の `[rs232c] tx_pin`/`rx_pin` で変更可能（デフォルト GP6/GP13）。
- ボーレートは `pb1000.ini` の `[rs232c] baudrate` で設定（デフォルト 9600 bps）。
- オン/オフは起動時の F1 セットアップメニュー（`[rs232c] enable`）で切り替え、
  保存後 MCU リブートで反映されます。
- EOF 受信（0x1A バイト）で自動 BREAK を発行する機能あり。

## 7. ジョイスティック

直結方式（PULL_UP 入力）のジョイスティックに対応しています。

| ボタン | デフォルトピン | デフォルト PB-1000 キー |
| :--- | :--- | :--- |
| UP | GP18 | カーソル上 |
| DOWN | GP19 | カーソル下 |
| LEFT | GP20 | カーソル左 |
| RIGHT | GP21 | カーソル右 |
| FIRE1 | GP26 | EXE |
| FIRE2 | GP27 | SHIFT |

- `pb1000.ini` の `[joystick]` セクションでキーマッピングを変更可能。
- オン/オフは起動時の F1 セットアップメニュー（`[joystick] enable`）で切り替え、
  保存後 MCU リブートで反映されます。
- ピンアサインの変更は `mp/main_input_joystick.py` の `JoystickInputManager.DEFAULT_PIN_MAP` を編集。

## 8. ステート管理

### Save State（F11）

**F11** を押すと、現在のセッション状態をプロファイルディレクトリに保存します。

- `ram0.bin`: 内部 RAM（8 KB）
- `ram1.bin`: 拡張 RAM1（有効時のみ）
- `ram2.bin` / `ram3.bin`: 拡張 RAM2 / RAM3（Bank2 / Bank3、有効時のみ）
- `regs.json`: CPU レジスタ（PC・フラグ・汎用レジスタ）
- `color_vram.bin`: カラー VRAM（VDP、192×64 = 12,288 B。VDP を実際に使っているプログラムの
  場合のみ保存される）

### RAM セーブ（エミュレータメニュー）

**RAM Save** でスナップショット単位の保存ができます。

- 保存先は `/sd/rams/<フォルダ名>/`。

保存したスナップショットを読み込みたい場合は、下記「自動ロード」の通り、System > Reboot
Emulator (MCU) で再起動してから起動時のプロファイル選択画面で選び直してください
（かつて EMULATOR MENU にあった **RAM Load** は 2026-08-22 に削除され、この手順に統一
されています）。

### 自動ロード

起動時に選択したプロファイルディレクトリ内のステートファイルを自動ロードします。
ファイルが存在しない場合はコールドブート。**リセットは行わずセーブした時点の PC・レジスタから
実行を再開します。**

> [!NOTE]
> 以前のバージョンでは、無人起動（プロファイル選択画面がタイムアウトし、誰もキー操作を
> していない状態）で壊れた/不整合なセーブを復元してハングし続けることを避けるため、この
> 自動ロードだけは RAM のみ復元して PC=0x0000（リセット）から起動する保守的な挙動でした。
> 現在はセーブ時点の PC・レジスタからの完全復元に統一されています。無人起動時の保険としては、
> 起動後 1.5 秒以内に CPU が KEY_INT 無効のままスリープしていないかを確認し、該当すれば
> 強制リセットする仕組み（`mp/main.py`の "Startup sleep detected" ガード）が別途あります。

## 9. スクリーンショット

**PrintScreen** キー、またはエミュレータメニューの **VRAM Save** で、PB-1000 の
エミュレート画面（192×32 または 192×64、モノクロ VRAM + カラー VRAM）をキャプチャします。
どちらも同じ処理（内部的には `_do_vram_save()`）を呼び出すため、結果は同一です。

- 保存先: `/sd/screenshots/`（SD カード非接続時は `/screenshots/`）
- 保存されるファイル（タイムスタンプ `YYYYMMDD_HHMMSS` 付き）:
  - `vram_<timestamp>.bin` / `.pbm`: モノクロ VRAM の生データ / PBM 画像
  - `edtop_<timestamp>.bin`: EDTOP バッファの生データ
  - `color_vram_<timestamp>.bin` / `.ppm`: カラー VRAM（VDP）が有効な場合のみ、生データ / PPM 画像

ベゼルやファンクションキーバーを含む**画面全体**をキャプチャしたい場合は、エミュレータメニューの
**Full Capture** を使用してください（次項参照）。

### 画面全体のキャプチャ（Full Capture）

エミュレータメニューの **Full Capture** は、ベゼル・PB-1000 画面・ファンクションキーバーを
含む物理ディスプレイ全体（例: 320×240 または 480×320）を 1 枚の PPM 画像として保存します。

- 保存先: `/sd/screenshots/full_<timestamp>.ppm`（VRAM Save と同じディレクトリ）
- 実装上、SPI 経由で実機の画面を読み出しているわけではなく、エミュレータが保持している
  VRAM・ベゼル配置・ファンクションキーバー画像から画面全体を再構成しています。そのため、
  キー入力時に一時的に表示されるステータスメッセージ（トースト表示）はキャプチャに反映されません。

## 10. 設定ファイル（pb1000.ini）

INI 形式の設定ファイルで動作をカスタマイズできます。全セクション・全キーの詳細な
リファレンス（デフォルト値、SD カード／プロファイル別 ini での上書き可否など）は
**[config_guide.md](config_guide.md)** を参照してください。

```ini
[display]
driver   = ILI9341          ; ILI9341 (320x240) または ST7796 (480x320)
scale    = 1.5               ; エミュレータ画面の拡大倍率（ILI9341=1.5, ST7796=2.0 推奨）
lcd_height = 32              ; 32=オリジナル / 64=拡張モード
rotation = 0                ; 0=通常 / 180=上下反転（基板の実装向きに合わせる）

[touch]
ili9341.y_offset = -10      ; ドライバ別プレフィックス付き key（§4・config_guide.md §9 参照）

[disk]
enabled  = true
path     = /sd/disks/disk1.img
```

設定値の意味・省略時のデフォルト・記述例は `pb1000.ini` 内のコメントおよび
[config_guide.md](config_guide.md) を参照してください。

## 11. HDMIミラー出力（オプション）

第2の Raspberry Pi Pico 2 ＋ HDMI出力アドオン（PICO-HDMI-PLUS 等）を接続すると、本体の
画面表示をHDMIモニターへリアルタイムでミラー表示できます。アドオンを持たない場合は
影響しません。配線は [hardware_guide.md](hardware_guide.md) §9、設定項目は
[config_guide.md](config_guide.md) §14 を参照してください。

**有効化**: `pb1000.ini` の `[hdmi] enable = true`、または起動時の F1 セットアップメニューで
切り替えられます。保存 → MCU リブートで反映されます（実行中に切り替える手段はありません）。

**LCDとHDMIは排他出力**です。HDMIが有効な間、物理LCD（およびステータスバー）への描画は
一切行われず、次の画面すべてがHDMI側にのみ表示されます:

- ゲーム画面（PB-1000のLCD VRAM・Color VRAM拡張）とベゼル
- 起動時のRAMプロファイル選択画面
- EMULATOR MENU

HDMI側では、ゲーム画面・ベゼル・メニュー・プロファイル選択画面がそれぞれ独立したレイヤーとして
中央寄せ表示されるため、画面サイズの異なるこれらの内容を切り替えても位置がずれることはありません。

> [!NOTE]
> 受信側ファームウェアの入手・ビルド方法は、独立プロジェクトの
> [`hdmi_bridge_receiver`](https://github.com/MobileFF/hdmi_bridge_receiver) を参照してください。

## 12. 常時時計表示（オプション）

エミュレータ実行中、画面右上に現在時刻を常時表示できます。`pb1000.ini` の
`[overlay] show_clock = true`（デフォルトは無効）で有効化します。設定項目の詳細は
[config_guide.md](config_guide.md) §15 を参照してください。

起動中だけ表示される §2 の「起動ステータス表示」の時計（Picoの内蔵RTCを表示）と設定キー
（`show_clock`）は共有していますが、実装は別物です。実行中のこちらは **PB-1000本体の
システム変数RAM上の `TIME$`/`DATE$` の値そのもの**を読み取って表示するため、BASICから
`PRINT TIME$` した場合と常に一致します（NTPを使っていない場合や、`TIME$`を
プログラムから直接変更した場合も含む）。1秒ごとに再描画され、ベゼル上端の余白（ゲーム画面や
FuncKeyBarとは重ならない領域）に表示されます。`[hdmi] enable = true` の場合は§11の排他方針
により表示されません。

---

## 13. 常時メモリ使用量表示（オプション）

エミュレータ実行中、画面**中央上部**に Pico 2 のヒープ空き容量を常時表示できます。`pb1000.ini`
の `[overlay] show_mem_free = true`（デフォルトは無効）で有効化します。設定項目の詳細は
[config_guide.md](config_guide.md) §15 を参照してください。

上記の常時時計表示と同じ仕組み（実行中のみ・1秒ごとに再描画）ですが、表示位置と内容が異なる
別機能です。値を読む前に `gc.collect()` は行わないため、実際に起きている空きメモリの逼迫や
断片化の様子がそのまま見えます。狭い画面幅で常時時計表示と同時に有効にすると、右上と中央上部の
表示が近接・重複する場合があります。`[hdmi] enable = true` の場合は§11の排他方針により
表示されません。
